# 2026-11-14 操作研修で検出した不具合の修正

## 動作変更

- 受注の登録・編集を `save_order_with_lines` RPCへ集約。所属会社をDB側で解決し、ヘッダーと明細を一括保存する。エラー時は全体をロールバックし、フォームの入力を保持してエラーを表示する。
- 金額はDB側で数量・単価・税率から再計算する。非課税0%を維持し、他社の商品・顧客やPOS同期受注の編集を拒否する。
- ダッシュボードで手入力受注のキャンセルも除外。既存のPOS計上条件は維持する。
- 未入金・銀行CSV消込候補・仕訳表示から下書き請求を除外する。既存レコードやステータスは書き換えない。
- 商品・顧客・仕入先の検索を接続。全角英数字の正規化、非該当0件、クリアによる再表示に対応。
- 新規見積・請求番号を日本時間の年度とUUIDで生成する。既存番号は変更しない。

## 適用順

1. `supabase_migration_atomic_order_save.sql` を対象DBへ適用する。
2. アプリをデプロイする。RPC未適用のままデプロイすると受注保存は失敗し、エラー表示になる。
3. 研修用受注だけで明細登録・数量変更・再読込を確認し、取消を維持する。実取引の更新・決済・外部送信は行わない。
4. 研修用下書き請求が未入金・仕訳から、取消受注がダッシュボードから除外されることを確認する。

関数はSECURITY INVOKERで既存RLSを維持する。匿名実行を許可しない。適用SQLは既存データの更新を含まず、消失済み明細の自動復元はしない。

## 検証コマンド

```
node --experimental-vm-modules --test tests/*.test.mjs
node node_modules/typescript/bin/tsc --noEmit
node node_modules/next/dist/bin/next build --webpack
```

`order-atomic.test.mjs` はPGliteの隔離DBを使い、本番に接続しない。明細挿入を強制失敗させて旧金額・旧明細の保持を検証し、正常編集・入力検証・他社データ拒否・匿名拒否・POS受注拒否・0%を確認する。
検索はローカルの一時画面で一致・非該当・全角英数字・クリアを実操作検証。一時ページは削除してからビルドする。

## 残る確認範囲

CSV実ファイルの取得・会計側取込、PDF実ファイル、決済、返品、スタッフ権限の通し確認は本変更の検証に含めない。顧客条件から支払期日を自動計算する追加仕様は含めない。
