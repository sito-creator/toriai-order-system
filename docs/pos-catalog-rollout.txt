Toriai POSカタログ拡張: 導入・検証手順 (2026-11-24)

1. 対象
商品画像、任意カテゴリー、POS表示設定を追加。既存の会計・Stripe・在庫RPCは変更しない。
ローカルの古いnext-webを上書きせず、最新main a646493から作業を作成。
source: toriai-pos-improvements

2. DB
本番では未適用。まずバックアップを取得し、Supabaseのステージング環境で
supabase_migration_pos_catalog_20261124.sql をSQL Editorまたはマイグレーション基盤から適用する。
既存のproducts/profiles/companies/get_my_company_idとSupabase Storageが必要。
既存POSのSQLマイグレーションが適用済みであること。

追加:
- product_categories (会社、名称、色、表示順、タブ表示)
- pos_display_settings (会社単位のカード形式/サイズ/画像/価格/順序/優先表示)
- products.category_id / image_path / pos_visible / pos_favorite / pos_sort_order
- products.pos_effective_price (standard_priceを優先する生成列。0円も優先)
- 会社を含む複合FK、画像パス制約、索引
- RLS、管理者チェック関数、名称同期トリガー、表示順更新RPC
- 非公開product-imagesバケット、会社別読込・管理者の追加/削除ポリシー

既存のカテゴリ文字列をカテゴリーに移行して商品を紐付ける。
カテゴリー削除時は商品を残して未分類にする。旧category列は互換のため維持。
このスキーマはローカルPostgreSQL互換環境で2回適用を検証。

3. ストレージ
company_assetsは既存の公開画像用途として変更しない。
今回の「他社からアクセス不可」要件は、新規の非公開product-imagesで実現。
JPEG/PNG/WebP (最大8MB/40MP)を実デコードし、静止WebP/最大800px/quality80に変換。
画像パスは認証済み会社IDから生成。クライアント指定パスは受け付けない。
GET /api/products/[id]/image はユーザーと所属会社を毎回確認し、Cookie付きで画像を配信。
Cache-Control: private, no-store。署名URLや公開URLをPOSに埋め込まない。
本番のStorageに広範な既存ポリシーがないかは、ステージング/本番で別途確認する。

DBの保存確認後に旧画像を削除する。保存失敗時の新画像も、
DBで未参照と確認できた場合だけ削除する。通信が不確実なら保持する。
不確実な失敗で残った未参照ファイルの自動削除は今回未実装。
定期保守では、24時間以上経過・自社パス・products.image_pathに未参照であることを
管理者が確認したうえで削除する。稼働中画像を一括削除しないこと。

4. 管理方法
商品管理 -> カテゴリー・POS表示設定 (/products/pos-settings)
会社owner/adminが作成・変更・削除・色・表示順・タブ表示を設定する。
PCはドラッグ、タッチ/キーボードは上下ボタンで並べ替える。
非表示は「タブのみ」を隠す。商品をPOSから除外する場合は商品のPOS表示をOFFにする。
商品は1カテゴリー。複数商品を選択して一括でカテゴリーやPOS表示を変更できる。
会計画面の「すべて」には、販売中かつPOS表示ONの商品を表示。
カードは画像/テキスト/コンパクト、小/標準/大、画像・価格の表示を選べる。
標準順/名称順/価格順と「よく使う優先」を設定できる。
設定は会社単位でDBに保存され、ユーザー個人のlocalStorageには依存しない。
一般メンバーは設定を閲覧できるが変更はできない。

5. 既存データとの互換性
新規マイグレーション未適用の環境では、POSは従来の表示にフォールバックし警告を表示。
新しい画像・設定機能はDB更新後のみ利用可能。
既存の商品編集・CSVのカテゴリ文字列は保持し、登録済みカテゴリー名には再紐付け。
CSV等で未登録の名前が追加された場合、文字列は維持するがPOSタブは自動作成しない。
管理画面でカテゴリーを作り、必要な商品に紐付ける。
カテゴリー名の変更は商品側の旧category列にも同期する。
データ取得は会社フィルター、60件ページング、検索220msデバウンス。
カテゴリーテーブルは最大1000件の表示・並べ替え、一括更新は最大100商品。

6. 検証コマンド
Node.js 22.6以降 (今回の実行環境は24.22.3)
npm ci --ignore-scripts
npm test
npx tsc --noEmit --incremental false
npm run build
新規POS関連ファイルへのESLintも実行 (結果は検証報告参照)。
既存アプリ全体には以前からLint指摘があるため、全体Lint成功とは記載していない。

7. 本番接続なしの画面デモ
TORIAI_POS_DEMO=1 とダミーNEXT_PUBLIC_SUPABASE_URL/ANON_KEYを設定し、
next dev --webpack --hostname 127.0.0.1 --port 3019 を起動。
http://127.0.0.1:3019/lp/pos-preview
実装したPOS・管理画面・商品画像フォームを同じコンポーネントで表示する。
画面上のAPIはメモリー内のモック。実決済・Supabaseへの保存はしない。
写真枠のイラストはテスト用。
NODE_ENV=productionの場合は環境変数があってもこのルートは404。
このデモを本番利用の代替にしないこと。

9. ロールバック
アプリだけ旧リリースへ戻せる。追加列/テーブル/非公開バケットは残してよい。
新しい設定や画像が保存された後にスキーマ/バケットを削除しない。
DB変更を取り消す場合はバックアップと運用停止計画を別途作成すること。
